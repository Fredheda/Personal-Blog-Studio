# AGENTS.md

Repo facts first, then the shared rules. A local session also reads the workspace `AGENTS.md` one level up.

PR titles and descriptions never mention Claude Code.

- **Merging:** the coordinator merges the bot and docs classes listed in the workspace `AGENTS.md` (Git); the owner merges everything else.

## What this is

Blog authoring studio (editor, AI writing agent; read-aloud audio comes later) behind Easy Auth, plus the blog read API, which is not public: only approved callers with an Entra token can use it. Posts, media and audio live in private Azure storage, never in this repo. The backend has the content model, blob storage layer, studio post service, studio post routes and the read API routes; the studio frontend lists, creates, edits, publishes and deletes posts in a Milkdown Crepe editor with a Preview toggle, a steps lane and the save state in the top bar (revisions BLOG-31, media BLOG-19 come later). The rest of the studio UI follows the system spec at `../docs/shared/specs/2026-11-08-blog-studio.md` (workspace root). Overview: `README.md`.

## Gotchas

- Public repo: never commit post content, media or audio. `.gitignore` carries the baseline.
- The read API is not public. Nothing client-specific (Portfolio or otherwise) belongs in this repo.
- `backend/` holds one Poetry project and two images. `Dockerfile.blogapi` copies `blog_core` and `blog_api` only; the read-API process must never import studio code or agent/LLM libraries (`backend/tests/test_apps.py` and `backend/tests/test_dockerfiles.py` pin both).
- `blog_core` also holds ids (`ids.py`), blob paths (`layout.py`), stored-document models (`models.py`) and the `BlobStore` interface (`store.py`). `AzureBlobStore` is the production store (managed identity); `tests/fake_blob_store.py` is the unit-test store (its default clock is earlier than any service clock: a test that needs blob times to count passes the service's clock). The store lists last-modified times (`modified_times`), which is how a body save counts as an edit without rewriting `draft.json`. Every blob path comes from `layout.py`. Change the store or the fake only together with `tests/test_store_contract.py`, which CI's `storage-contract` job also runs against Azurite (by hand: `DEPLOYMENT.md`, "Storage tests against Azurite").
- Markdown parsing (`markdown-it-py`, `mdit-py-plugins`) is in Poetry group `studio`, installed by `Dockerfile.studio` only; `studio_api.markdown.validate_body` is the publish-time check (no raw HTML, `https:`/`#anchor`/relative links only). Maths is checked too (`studio_api/maths.py`, not KaTeX): no `$$$` fence, no unescaped `$` inside a formula (`\text{}` and `\$` are fine), balanced braces, matching `\begin`/`\end`, paired `\left`/`\right`; each problem has its line and says "one formula per maths block". `studio_api.posts.PostService` holds no state; publish writes the snapshot first and `index.json` last.
- Studio routes (`studio_api/routes.py`) are a thin layer over `PostService`; every non-GET needs header `X-Blog-Studio: 1` (and a listed `Origin` when `BLOG_STUDIO_ORIGINS` is set); body, meta, restore and publish need `If-Match`. Errors are problem+json (`blog_core.problem`). Draft responses and list items carry `published`, `version`, `publishedAt` (first publish) and `versionPublishedAt` (when the current version went live), all from `index.json` read once per call, drafts also `slugLocked`; `updatedAt` is the later of the details save and the body save. `GET /posts/{id}/check` answers what publish would refuse on for the saved post (read-only; publish and check share `PostService._blockers`). `DELETE /posts/{id}` takes any post down and removes every blob (`draft.json` last, so a failed delete is finished by pressing Delete again; publish undoes its own writes when `draft.md` is gone after its index write); a post that was ever published needs `?confirm=published`, otherwise 409 with problem `type` `urn:blog-studio:confirmation-required`. Deleted blobs stay recoverable for 7 days (account soft delete); `DEPLOYMENT.md` has the restore steps. `openapi/v1.json` is the read API `v1` contract with examples.
- The read API (`blog_api`) serves `/v1` from `blog-published` only. The platform validates the token and injects `X-MS-CLIENT-PRINCIPAL`; `blog_api/principal.py` checks the `Blog.Read` role from it (401 without a principal, 403 without the role), so platform authentication must stay enabled. Media links are 10-minute read-only user-delegation SAS (`blog_api/media.py`). `openapi/v1.json` must match the generated schema (`tests/test_openapi_contract.py`); a contract change needs a `docs/api-changelog.md` entry and the new `info.version`.
- Apps are built through `blog_core.app_factory.create_base_app`: interactive docs and OpenAPI are off unless an app passes its own `openapi_url`. It also caps every request body at 1 MiB (413 problem+json, also for a chunked body: reading stops past the cap and the app's own answer, a framework 400 included, is replaced by the 413) and answers unknown paths and wrong methods with problem+json (`backend/tests/test_base_app.py`).
- The browser reaches the studio API only through the web app's route handler `/api/studio/...` (`frontend/lib/proxy.ts`): `/posts` allowlist, no query string except exactly `confirm=published` on `DELETE /posts/{id}`, 1 MiB cap, bearer token from the web app's managed identity (none when `STUDIO_API_AUDIENCE` is unset, the local-run case), the browser's `X-Blog-Studio` and `Origin` forwarded unchanged and never added by the proxy, no CORS headers and no OPTIONS handler (Next's automatic OPTIONS only sets `Allow`, so a cross-origin preflight still fails). Keep it that way: the studio API's same-origin guard relies on it. The proxy waits 60 s (the studio API scales to zero and starts in about 30 s), answers a timeout with a 504 "waking up" problem, and logs one line per upstream answer (status, content-type, length, `server`, `www-authenticate`; never tokens, cookies or bodies): `az containerapp logs show -g rg-chatbot -n ca-blogstudio-web --type console`. A 403 with no proxy line was answered before the proxy (the web app's own Easy Auth or ingress).
- **Next.js 16 and React 19 are newer than most training data.** Read the guide under `frontend/node_modules/next/dist/docs/` before writing frontend code.
- npm is pinned to 12.2.2 in every Dockerfile stage and every CI job that uses `actions/setup-node` (needs Node `^24.15.0 || >=26`; `backend/tests/test_npm_pin.py` enforces one version everywhere). npm 12 blocks dependency install scripts unless `frontend/package.json` `allowScripts` lists them; approve a needed script with `npm install-scripts approve <pkg>`.
- Dependencies: `frontend/.npmrc`, `frontend/e2e/azurite/.npmrc` and `backend/poetry.toml` make npm and Poetry resolve only versions at least 14 days old (Dependabot's window); `npm ci` and `poetry install` install the locked versions and are not affected. A security fix younger than 14 days is taken only on the owner's yes for that package and version, with a one-off `npm install <package>@<version> --min-release-age-exclude=<package>` or `POETRY_SOLVER_MIN_RELEASE_AGE_EXCLUDE=<package> poetry update <package>`; never commit an exclusion. Poetry (2.5.1) and pip (26.2.2) are pinned exactly in `ci.yml`, `security.yml` and both backend Dockerfiles: bump them together. GitHub Actions are pinned by commit with the release as a comment; Dependabot updates them. Every Docker image is pinned as `<tag>@sha256:<digest>`: the Dockerfile `FROM` lines (Dependabot proposes their digest updates) and the gitleaks, actionlint and Azurite `docker run` images, which are bumped by hand: `docker buildx imagetools inspect <image>:<tag>`, then copy the top-level `Digest` (the multi-platform index) into every reference to that image (gitleaks: `security.yml` and "Security checks" below; actionlint: `ci.yml` and `scripts/ci-local.sh`; Azurite: the same two, on the version `frontend/e2e/azurite` locks). `backend/tests/test_supply_chain.py` fails the PR when a rule is broken.
- Styling is Tailwind CSS v4 (`postcss.config.mjs`, `@import "tailwindcss"` in `app/globals.css`). The studio tokens (spec 7.1) are `--color-*` in the `@theme static` block of `globals.css`: use them as utilities (`bg-pane`, `text-muted`) or `var(--color-*)`; `frontend/lib/contrast.test.ts` fails when a text pair drops below 4.5. Preflight is on: an element needs a base rule or a class to look like anything (the page `h1`, `p` and links have base rules in `globals.css`). The Preview is `.post-body` (also the class later pages share), highlighted by rehype-highlight with the public blog's options (`common` languages plus MATLAB, `plainText` for `math`, `text`, `txt`); its type rules (headings, paragraph line height, links, inline code) are one unlayered rule shared with the editor (`.crepe-host .milkdown .ProseMirror`), so the two cannot drift. The editor is Crepe's dark theme with its variables mapped to the tokens as spec 7.4 lists them (`.crepe-host .milkdown`; `outline` is `muted`, owner 497), code blocks on `deep` by an unlayered three-selector rule (Crepe's own is more specific than a CodeMirror theme), and a CodeMirror theme built on the same variables (`lib/code-theme.ts`). Never import Crepe's `common/style.css` or `latex.css` or any font; `globals.css` may not contain `url(` (hardening test).
- Shared studio components live in `frontend/components`: `Button` (default look from the base rule in `globals.css`; `variant="primary"` is the white one), `Pill` (status: Draft ring, Published dot), `MessageStrip` (`conflict`, `warning` (amber) and `error` are `role="alert"`, `success` is `role="status"`; `ProblemList` renders the error strip) and `Dialog` (a modal question: Esc, the backdrop and the cautious button cancel; focus starts on the cautious button and returns to where it was; `Sheet` is the bottom-sheet version, both share `useModal`). The theme removes Tailwind's default colours, so `bg-black` and `text-white` produce no rule: use the tokens (`bg-deep/70`). The posts list asks before a delete in `Dialog`s: a post that is published now gets the post dialog once and is deleted with `confirm=published`; any other post gets the draft dialog, and the API's confirmation answer (`isConfirmationRequired`) opens the post dialog.
- The post page is a lane and a column (`PostEditor`). The steps lane (`StepsLane`, views from `lib/steps.ts`) is sticky beside the page; the save state, Preview (a toggle), Save and Publish sit in the top bar, which is sticky too: `TopBar` renders a slot (`TopBarSlot`) and `PostEditor` portals `TopBarActions` into it. `lib/use-check.ts` asks `GET /posts/{id}/check` when the post has loaded and after every successful save or reload (answers with other ETags are dropped). Publish needs a saved post and a check without problems (`publishGate`); a failed check does not block it, and a conflict switches Save and Publish off. A publish the server refuses lists its problems under Check with the amber strip. Below 760px the lane is hidden: `StepChips` show the steps (the Check chip opens the problems and the Publish chip the Publish step with Unpublish, each in a `Sheet`) and Preview and Save form a fixed bottom bar. A problem with a line is a button (lane and sheet): `CrepeEditor`'s `jumpToLine(line, markdown)` moves the caret to the editor block that holds the line of the saved text (`lib/line-map.ts`: one block per top-level Markdown block, `definition` nodes skipped, one trailing empty paragraph allowed; any other block count is not trusted and a strip says the line was not found). In code and table blocks the scroll is sure, the caret less so.
- Fonts are system stacks only: no font file, `@font-face` or `next/font` (owner rule; `frontend/tests/hardening.test.ts` enforces it). Maths renders as MathML, never with bundled maths fonts.
- Every local server binds `127.0.0.1` only (workspace rule for local runs): `npm run dev` and `npm run start` carry `--hostname 127.0.0.1` (Next binds `0.0.0.0` by default), the browser-test servers and the Azurite command in `DEPLOYMENT.md` name the loopback host, and `frontend/tests/hardening.test.ts` fails when one of them loses it. The Docker images keep `0.0.0.0` on purpose (the container ingress must reach them). Check a started server with `lsof -nP -iTCP:<port> -sTCP:LISTEN`: it must show `127.0.0.1`, not `*`.
- Complete local runs use dev containers, never the real posts: `blog_core/layout.py` reads `BLOG_DRAFTS_CONTAINER` and `BLOG_PUBLISHED_CONTAINER` (unset means the production names; `tests/test_infra_bicep.py` pins that the Bicep values equal the defaults; equal or malformed names refuse to load). `scripts/setup-dev-storage.sh` (dry run unless `--apply`; Azure change, the owner's yes) creates `blog-drafts-dev` and `blog-published-dev` and the user's container-scoped data role, and fails when the user holds any other blob data role. `backend/dev_support/seed.py` seeds three posts only when the API's posts equal the dev drafts container's. Steps: `DEPLOYMENT.md`, "Complete local run".
- `next dev` writes untracked `frontend/AGENTS.md` and `frontend/CLAUDE.md` when it detects an AI agent. Delete them, or start with `env -u AI_AGENT -u CLAUDECODE`.
- The studio editor is Milkdown Crepe (`frontend/components/CrepeEditor.tsx`, client-only through `next/dynamic`); Markdown stays the source of truth and `frontend/tests/fixtures/crepe-output/` plus `backend/tests/test_editor_fixtures.py` keep what it writes valid for `validate_body` (`lib/normalise.ts` turns an HTML line break into what the validator accepts). Maths is MathML only (`katexOptions.output: "mathml"`): Crepe's `theme/common/style.css` and `latex.css` import KaTeX's stylesheet and with it its fonts, so `CrepeEditor.tsx` imports the theme parts one by one and `app/globals.css` carries the maths popup rules; never import either file. The studio sends `Content-Security-Policy: img-src 'self' data: blob:; media-src 'self'`, and `npm run build` fails on any font file under `.next/static` (`scripts/check-no-fonts.mjs`). Only the body autosaves (`lib/autosave.ts`: one save loop, stops on a 412, after any other failure waits for the next edit or Save; never retry on a timer); details save through the one Save button (`saveAll()` in `PostEditor`); Publish stays disabled while anything is unsaved.
- `frontend/lib/token.ts` is `server-only` (the managed-identity token never reaches the browser bundle); `tests/hardening.test.ts` fails when a `"use client"` file reaches it, directly or through other modules. Proof method: a client component that imports AND uses it fails `npm run build` (an unused import is dropped before the check).
- Browser tests (`frontend/e2e/*.spec.ts`, Playwright) run the production build against the real studio API (`backend/e2e_support/studio_app.py`, copied by no Dockerfile) on in-memory Azurite, with only the managed-identity token endpoint faked (`frontend/e2e/msi.ts`). Azurite is its own locked package, `frontend/e2e/azurite/` (exact version, own lockfile, installed with `npm ci --prefix e2e/azurite`, Dependabot-watched; never a bare `npx`). Each test seeds its own post through the API and no test assumes an empty list; each UI ticket adds one browser test per flow it ships. Easy Auth, Entra tokens and cold starts are not covered; 500, 504 and slow answers stay unit tests of the proxy.
- `GET /healthz` (both apps) is the path Easy Auth and token validation exclude; keep it free of data.

## AI PR review

`.github/workflows/claude-review.yml` reviews each PR once it is ready, on later pushes, and when the owner comments `@claude`; the review is comment-only and ends with an advisory `Verdict:` line (`ready to merge`, or `changes requested (N open)` with the findings). Secret: `CLAUDE_CODE_OAUTH_TOKEN` (repo secret; expires about 2027-11). Fallback if subscription auth is refused: use `anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}` in both jobs. Fork PRs, drafts and bot PRs are skipped, except Devin and Claude (allowlisted in the job `if` and `allowed_bots`); Dependabot never gets a review. Do not require the `Claude Review` job as a status check: it skips on PRs that change the workflow file.

## Shared rules (identical in every repo; never edit here)

Copied from the owner's template. The `shared-block` rule fails CI when this block differs from it.

**Ownership.** You own this codebase: keep it maintainable, secure, free of bugs, duplicated code and needless comments. Fix tech debt you meet in the files you touch.

**Tickets.** Work only the ticket assigned to you; one ticket is one PR. Keep its Jira status true: `In Progress` on start and while the PR is open, `Done` only after merge and cleanup. Record decisions, steps and open questions on the ticket, not in chat. A question for the owner goes on the ticket as one exact question; keep working on what does not depend on it. Start every ticket or PR comment with your agent name in brackets, such as `[Claude Coding Agent]` or `[Devin Coding Agent]`.

**Git.** Work on a feature branch; never push to `main`, force-push, rebase or reset a shared branch, or delete a branch you did not create. Commit messages: 2 lines at most, no trailer. The owner alone reviews, approves and merges; hand over the PR URL and wait.

**Pull requests.** At most 25 changed files and 5000 changed lines (lockfiles, fixtures, generated files and `docs/` excluded); the `pr-size` rule fails a larger PR unless the owner set the label `size-override`. Open a draft first. Before asking for review run `scripts/ci-local.sh` until it passes, then wait for CI, the security checks and the automated review, and fix or answer every comment. A PR that changes what a user sees carries a screenshot or a short video when you cannot offer a local run.

**Tests first.** Write and run each behaviour's failing test before the code. Every test must catch a bug no other test catches; remove a test that does not. Never commit a test that only proves something was removed: show that evidence once in the PR description. A test of behaviour the code still has stays, also when it asserts that something is refused or not forwarded.

**Comments.** The default is no comment. Keep or add one only for a reason the code cannot show (a constraint, a security reason, a workaround with its source). When you edit a file, delete every comment in it that restates the code, narrates a change or points at a ticket, and every redundant test, in the same PR, in a separate commit; delete aggressively, git history keeps the rest. The `comment-count` rule fails a PR in which a file's comment count grows, unless the PR description has a line `Comments: <path>: <reason>` for that file.

**Specs and plans.** A non-trivial ticket has a spec in `docs/specs/` and a plan in `docs/plans/` (`YYYY-MM-DD-slug.md`, the plan uses the spec's slug). They merge as a docs-only PR before the code PR; the ticket description names both paths. Never move a merged spec or plan; the code PR sets `Status: done (PR #n)` in its header.

**Nothing sensitive in the repo.** No secret, key or `.env` file. No Azure resource id, subscription, tenant or client id, no host that is not public, and no open weakness in code, docs, specs or plans: those go on the ticket only.

**Dependencies.** Add or update only with the repo's package manager, inside the repo. Never pass a flag or variable that relaxes the 14-day release cooldown.

**Deploys and cloud changes.** Only on the owner's explicit yes for that one run, recorded on the ticket. Never approve a waiting deployment.

**Rules a machine checks.** `scripts/rules/run.sh` runs them, locally and in the CI job `rules`. Fix what a rule reports; never bypass or weaken a rule to pass. A correction from the owner becomes a new rule there, not a sentence here.

**Docs.** Every PR updates the docs it makes untrue. Edit `AGENTS.md`; `CLAUDE.md` only imports it.
